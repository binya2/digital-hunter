# Digital Hunter - Real-Time Target Management System

מערכת מבוזרת לניהול ובניית תמונת מטרות בזמן אמת, המבוססת על ארכיטקטורת מיקרו-סרוויסים ומטפלת בזרמי נתונים מורכבים של מודיעין, תקיפות והערכת נזק.

##  איך להריץ את הפרויקט

 ההרצה היא פשוטה ודורשת פקודה אחת בלבד. 

### דרישות קדם
- Docker ו-Docker Desktop מותקנים.
- Docker Compose פעיל.
- הריצו את הפקודה הבאה:
   ```bash
   docker-compose up --build
   ```

גישה לכלים:

Kibana: צפייה בלוגים ובדאשבורדים בכתובת http://localhost:5601.

Postgres: בסיס הנתונים זמין בפורט 5432.

Logs: ניתן לראות את הלוגים זורמים בתוך קיבאנה באינדקס intel-logs.

## טכנולוגיות והשימוש בהן

בפרויקט זה נבחרו טכנולוגיות שלמדנו בהכשרה, תוך שילוב ביניהן ליצירת מערכת חסינה:

- Kafka: משמש כעמוד השדרה  להעברת אירועים בין השירותים. בחרנו בו בגלל היכולת לטפל בכמויות אדירות של דאטה בזמן אמת והפרדה מוחלטת  בין יצרני המידע לצרכנים.

- PostgreSQL: בסיס הנתונים המרכזי המנהל את "בנק המטרות". נבחר בגלל התמיכה בטרנזקציות ACID, המבטיחות את אמינות הנתונים  גם בתנאי עומס ועדכונים מקביליים.

- Elasticsearch & Kibana: תשתית ניהול הלוגים של המערכת. כל שירות מדווח על פעולותיו, שגיאות לוגיות וחריגות ישירות לאלסטיק לצורך ניטור ותחקור מהיר.

- Python (Pydantic): שפת הפיתוח המרכזית. השתמשנו ב-Pydantic לביצוע ולידציה קשיחה של ההודעות הנכנסות מקפקא, מה שמבטיח שרק דאטה תקין ייכנס למסד הנתונים.

- Docker & Docker Compose: ניהול מלא של מחזור חיי האפליקציה. מאפשר הרמה של תשתיות מורכבות ומיקרו-סרוויסים בסנכרון מלא בעזרת Healthchecks מובנים.

## ארכיטקטורה: למה ואיך?
המערכת בנויה בארכיטקטורת Microservices מבוססת אירועים (Event-Driven Architecture).

למה בחרנו בארכיטקטורה הזו?
- Scalability (יכולת גידול): כל שירות הוא עצמאי. ניתן להגדיל את כמות הצרכנים (Consumers) של שירות מסוים כדי לעמוד בעומסי מידע מבלי לשנות את קוד המערכת.

- Resilience (חסינות): המערכת מתוכננת לשרוד נפילות. אם מסד הנתונים או שירות מסוים יוצאים מכלל פעולה, ההודעות נשמרות בבטחה ב-Kafka ומעובדות מיד עם חזרת השירות.

- ניהול שגיאות מתקדם (DLQ): הטמענו מנגנון Dead Letter Queue. הודעות שאינן עוברות ולידציה מבנית (Pydantic) או סותרות את הלוגיקה העסקית (למשל, תקיפה על מטרה שהושמדה) מנותבות ל-Topic ייעודי לתחקור, מבלי לעצור את הרצף המבצעי של שאר המערכת.

## רכיבי המערכת:
- Simulator: מדמה זרם נתונים מבצעי הכולל "הזרקות" מכוונות של שגיאות JSON, שדות חסרים וסתירות לוגיות כדי לבחון את חוסן המערכת.

- Intel Service: המוח המודיעיני. קולט אותות, מחשב מרחקים (Haversine) ומהירות ממוצעת (בונוס) ומעדכן את מיקום המטרות.

- Attack Service: שומר הסף של התקיפות. מוודא שכל תקיפה רשומה כחוק ומונע בזבוז תחמושת על מטרות שכבר הושמדו.

- Damage Service: מעדכן סטטוס נזק סופי תוך ביצוע הצלבות נתונים (Data Validation) מול פרטי התקיפה המקוריים ב-DB.

- Shared Library: ספרייה משותפת המרכזת את התקשורת מול Kafka ו-Postgres וניהול הלוגים, תוך שמירה על עקרון ה-DRY וקוד נקי.
